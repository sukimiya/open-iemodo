# Customer-Facing Storefront & Marketing Strategy

## Context

后端已具备产品目录、客户认证、订单、支付、优惠券、评价、售后等核心能力，但面向客户的 storefront 门户尚未构建。本文从"客户侧门店必要模块"和"提高留存的营销模块"两个维度梳理缺口并制定优先级。

---

## 一、基础设施缺口（门店必需）

这些是客户网站能跑起来的前提，缺了体验就不完整：

### 1.1 购物车 (Cart)

当前没有服务端购物车。可行方案：

| 方案 | 复杂度 | 优缺点 |
|---|---|---|
| **客户端 localStorage** | 低 | 即刻可用，但跨设备无法同步，丢了数据 |
| **服务端 Cart（Redis）** | 中 | 持久化，支持跨设备，支持未登录加购（guest cart），最适合电商 |
| **数据库 Cart 表** | 中 | 持久化但查询开销大 |

**推荐**：Redis 存储购物车（`cart:{customerId}` 或 `cart:{sessionId}`），guest cart 在登录后合并。

### 1.2 客户地址管理

地址目前只在 `user-service` 给 admin 用户用。客户需要：
- 新增/编辑/删除收货地址
- 设为默认地址
- 下单时选择地址

需在 customer-service 新增 `CustomerAddressController` + 对应的 `addresses` 表。

### 1.3 运费计算

后端 `fulfillment-service` 有内部仓库分配和投递预估，但没有客户在结算页看到的"可选承运商+运费列表"。需要在 fulfillment-service 新增公开端点。

### 1.4 密码重置 & 邮箱验证

当前注册即登录，没有验证邮箱环节，也没有"忘记密码"流程。标准做法：
- 注册后发验证邮件 → 点击链接激活
- "忘记密码" → 邮件发送重置链接/验证码 → 重设密码

### 1.5 产品搜索增强

当前 `/search?q=...` 仅全文检索，缺少：
- 价格区间过滤
- 排序（价格、销量、评分、新品）
- 属性筛选（规格、颜色、尺寸等）

### 1.6 订单追踪

`OrderDTO` 没有物流单号字段，客户无法追踪"到哪儿了"。需在订单下单后 push 物流信息。

## 二、营销与留存模块（可选，按 ROI 排序）

以下是当前主流的电商留存手段，结合 IEMODO 现有架构评估落地难度：

### 第一梯队：高 ROI，快落地

#### 2.1 会员积分体系 (Loyalty Points)

**做什么**：下单/评价/签到 → 攒积分 → 抵扣金额或兑换优惠券

**现有基础**：customer 域已有用户身份，订单和评价事件存在，只需新增积分记录表和结算逻辑。

**落地难度**：中低。核心链路：事件 → 积分入账 → 积分查询 → 兑换/抵扣。

#### 2.2 优惠券中心页 + 裂变活动

**做什么**：客户可见的优惠券展示页面，限时领取、新人专享、邀请好友得券

**现有基础**：marketing-service 已有完整优惠券引擎（创建、发布、认领、验证、计算），缺的是面向客户的展示页和自动派发规则。

**落地难度**：低。后端几乎不需要改动，主要是前端页面 + 加一个"新注册自动发券"规则。

#### 2.3 邮件自动化 (Transactional + Marketing Email)

**做什么**：
- 欢迎邮件（注册后）
- 订单确认邮件
- 发货通知邮件
- 弃购挽回邮件（加购未下单，N小时后提醒）
- 复购提醒（上次下单N天后）

**现有基础**：notification-service 已有邮件发送能力 + 模板引擎。缺的是触发规则和定时扫描。

**落地难度**：低。notification-service 已具备发送能力，需要新增触发逻辑。

### 第二梯队：中 ROI，需要一定投入

#### 2.4 个性化推荐 (Product Recommendations)

**做什么**："猜你喜欢"、"购买此商品的顾客也买了"、"浏览历史的相似商品"

**落地难度**：中等。简单版（协同过滤）可基于订单数据做关联推荐。复杂版需要埋点+ML。先做规则版（同类目推荐、热销推荐），`ProductController` 已有 `featured` 和 `new-arrivals` 端点可扩展。

#### 2.5 限时闪购 (Flash Sales)

**做什么**：特定商品限时特价，倒计时，营造紧迫感

**落地难度**：中等。需要：
- 闪购活动管理（admin 端已有基础）
- 客户侧展示（倒计时进度条、已抢百分比）
- Redis 预热库存缓存应对瞬时流量

#### 2.6 客户分层 & 会员等级

**做什么**：Silver/Gold/Platinum 等级，按消费金额升级，不同等级享受不同折扣/免邮

**现有基础**：Customer 实体已有 `totalOrders`、`totalSpent` 字段，可在这些字段上叠加等级逻辑。

**落地难度**：中等。需要定义等级规则、升级/降级逻辑、等级权益注入到价格计算。

### 第三梯队：高 ROI 但需要较多投入

#### 2.7 推荐返利 (Referral Program)

**做什么**：老客户邀请新客户 → 新客户首单后 → 双方各得优惠券/积分

**落地难度**：中高。需要唯一邀请链接/码、追踪邀请关系、发放双方奖励。

#### 2.8 推送通知 (Push Notifications)

**做什么**：浏览器/App 推送，促销活动通知、订单状态更新

**落地难度**：中高。需要 VAPID 密钥管理、Service Worker（浏览器）、FCM/APNs（App）、客户订阅/退订管理。

#### 2.9 直播带货 / 短视频商品

**做什么**：直播展示商品 → 点击购买，短视频种草

**落地难度**：高。需要直播推拉流基础设施 + 实时互动。除非有明确商业模式，否则优先级靠后。

## 三、推荐路线图

### Phase 1：让客户能买东西（基础设施）

| 优先级 | 模块 | 预估工作量 |
|--------|------|-----------|
| P0 | 客户端购物车（Redis） | 2-3天 |
| P0 | 客户地址管理 | 1-2天 |
| P0 | 运费查询（结算页） | 1-2天 |
| P1 | 产品搜索增强（排序+过滤） | 1-2天 |
| P1 | 密码重置 & 邮箱验证 | 1-2天 |

### Phase 2：让客户愿意留下（营销基础）

| 优先级 | 模块 | 预估工作量 |
|--------|------|-----------|
| P1 | 会员积分体系 | 3-4天 |
| P1 | 邮件自动化（欢迎+订单+弃购） | 2-3天 |
| P1 | 优惠券中心页 + 新人自动发券 | 1-2天 |
| P2 | 订单物流追踪 | 1-2天 |

### Phase 3：让客户多买（进阶营销）

| 优先级 | 模块 | 预估工作量 |
|--------|------|-----------|
| P2 | 个性化推荐（规则版） | 2-3天 |
| P2 | 客户分层 & 会员等级 | 2-3天 |
| P2 | 限时闪购 | 3-4天 |
| P3 | 推荐返利 | 3-4天 |

---

## 四、下一步建议

如果你打算先做客户门店，建议从 **Phase 1 的 5 个模块**开始——这是让客户能够完成一次完整购物的最小闭环。Phase 2 的积分+邮件+券中心可以在初期通过简单规则快速上线，不需要复杂系统。
